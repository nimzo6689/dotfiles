# 0001: chezmoi による dotfiles の管理を開始する

* ステータス: 承認済み (Accepted)
* 日付: 2026-09-07

## 文脈 (Context)
これまで dotfiles の管理・同期が手順書（Gistで管理）での手動操作になっており、以下の課題が発生していた。

* Windows と WSL との間で、設定内容の管理が分断されている。
* 設定ファイルが増えるたびに、手順が増えて時間がかかる。

## 検討した選択肢 (Options Considered)
* **選択肢1: 自作スクリプト(Bash & PowerShell)**
  * 長所: 外部ツールへの依存がない。仕組みがシンプル。
  * 短所: 
    * Windows と WSL とで、設定内容を重複して管理する必要がある。
    * Bash スクリプトの可視性が悪く、メンテナンスコストが高い。
* **選択肢2: Ansible**
  * 長所: Playbook の記述により、設定内容の可視性が高く、メンテナンスコストが低い。
  * 短所: Windows では Ansible が動作しないため、 WSL 上での実行が必須となる。
* **選択肢3: chezmoi(Nushell & PowerShell)**
  * 長所: 
    * 実ファイルを直接リンクするのではなく、`chezmoi apply` で生成・配置するため安全。
    * Goのテンプレートエンジンが使え、OSやホスト名に応じた条件分岐が容易。
    * Bash の代わりに Nushell を使うことで、可視性の高いスクリプトを記述できる。
  * 短所: コマンドやディレクトリ構造（`dot_` プレフィックス等）に固有のルールがあり、学習コストがわずかにある。

## 決定 (Decision)
**chezmoi を採用し、dotfiles の全般管理を開始する。**

テンプレート機能によるマルチOS対応の容易さと、将来的に秘匿情報（APIキー等）を安全に組み込める拡張性を評価し、chezmoi が最適と判断した。

## 結果とトレードオフ (Consequences)
* **良い影響 (Positive):**
  * `chezmoi init <repo>` コマンド一発で新しい環境の初期構築が完了するようになる。
  * OSごとの設定差分を `{{ if eq .chezmoi.os "darwin" }}` などのテンプレート記述で1つのファイル内に綺麗にまとめられる。
* **ネガティブな影響・トレードオフ (Negative):**
  * 設定変更時に `~/.config/...` を直接編集した後、`chezmoi re-add` や `chezmoi edit` を通してソースを更新する運用フローを意識する必要がある。
